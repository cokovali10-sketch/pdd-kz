# JolBilet v2 — план улучшений (дизайн, мобильная версия, обучение) + программа проверки

Документ фиксирует: что улучшаем, в каком порядке, как проверяем результат и где
заранее видны дефекты. Работать по фазам; каждая фаза заканчивается зелёным
`tsc`, `vitest`, `build` и (с Фазы 1) браузерным прогоном.

---

## 0. Контекст

Уже есть: контент (45 вопросов, 65 знаков, разметка, ПДД, штрафы), 10 режимов,
экзамен с таймером и разбором, SRS, достижения, локальный профиль + sync-код,
PWA, ТОПы, командная палитра.

Слабые места (по коду, не по ощущениям):

1. **Один файл стилей на 1200 строк** — дубли, нет слоёв, трудно менять.
2. **Нет дизайн-токенов для плотности и размеров** — базовый размер 16px зашит жёстко.
3. **Мобильный экзамен**: свайпов нет, сетка вопросов мелкая, «Далее» внизу —
   надо дотянуться; таймер и прогресс занимают место.
4. **PWA неустанавливаема**: в манифесте только SVG-иконка, `apple-touch-icon`
   ссылается на несуществующий PNG.
5. **Таблицы на телефоне** без `data-label` → подписи в карточках пустые.
6. **Нет реального учебного алгоритма**: диагностики, плана подготовки, прогноза
   готовности, «что учить сегодня».
7. **Обратная связь по контенту** отсутствует — ошибки в вопросах некому сообщить.
8. **Тесты** покрывают логику, но не хранилище (нет `fake-indexeddb`) и нет e2e.
9. **SEO**: SPA без пререндера — «мега крутой» сайт не найти в Google.
10. **i18n**: 3 языка всегда в бандле (~25–30 KB gzip), `document.lang` не
    обновляется.

## 2. Фаза A — Дизайн-система v3 (фундамент)

**A1. Разбить CSS на слои** (`src/styles/`):
`tokens.css` (переменные, темы, типпошкала) · `base.css` (reset, типографика,
фокус, скроллбар) · `layout.css` (app/sidebar/topbar/mobile-nav) ·
`components.css` (кнопки, карточки, поля, таблицы, модалки) ·
`features.css` (экзамен, диаграммы, знаки, heatmap, палитра) · `utilities.css`.
Импорт в `global.css` через `@import` (Vite склеит).

**A2. Токены**: добавить `--space-1..9`, `--text-xs..3xl`, `--tap-sm: 36px`,
`--tap: 44px`, `--tap-lg: 52px`, `--content-max`, `--sidebar-w`, `--topbar-h`,
`--z-*`, `--dur-fast/slow`. Все компоненты — только через токены (запрет на
магические px в новых правилах).

**A3. Типографика**: модульная шкала с `clamp()`, `text-wrap: balance` для
заголовков, `text-wrap: pretty` для абзацев, `font-variant-numeric:
tabular-nums` для всех чисел, `hyphens: auto` для kk (длинные слова).

**A4. Компоненты, которых не хватает** (создать, использовать):
`Sheet` (bottom-sheet на мобильном / popover на ПК) · `Tabs` · `Toast`
(вместо `alert`/`window.alert`) · `Tooltip` (CSS-only, для «почему так») ·
`Toggle` (переключатели настроек) · `Slider`? (не нужен) · `Stat` (единый) ·
`EmptyState` (единый) · `Skeleton` (варианты: text/card/grid).

**A5. Иконочная система**: единый размер (`16/18/20`), `stroke-width: 1.8`,
никаких emoji в UI-подписях (сейчас есть `🔥`, `★`, `◈` — заменить на lucide
`Flame`, `Star`, `Signpost`).

**A6. Контраст и доступность**: прогнать Axe, поднять `--fg-faint` минимум до
4.5:1 на `--surface`, проверить фокус-кольца, `aria-*` на всех интерактивных
элементах, корректный `aria-label` у `role="radiogroup"`.

**Критерий готовности A:** Axe — 0 serious; страницы не сломаны визуально;
`pnpm lint` чист; бандл CSS ≤ 26 KB gzip.

## 3. Фаза B — Мобильная версия (приоритет P0)

**B1. Навигация**
- 5 слотов + «Ещё» (Sheet со всеми разделами), активный слот подсвечен.
- Прямой доступ к «Продолжить тренировку» из нижней панели ( FAB-кнопка по центру ).

**B2. Экзамен на телефоне**
- Свайп влево/вправо между вопросами (с порогом 60px и без конфликта с
  вертикальным скроллом), тактильный отклик `navigator.vibrate(10)`.
- Нижняя панель: «Назад · Далее · Пауза», прогресс-полоса над ней.
- Сетка вопросов — в Sheet (не в `<details>`), с цветовой легендой.
- Крупные опции: `min-height: 56px`, `font-size: 16px`, номер варианта виден.
- Таймер: компактный чип, при < 60 с — пульсация + вибрация.
- Автоскрытие мобильной навигации на время экзамена (чтобы не съедала экран).

**B3. Тач и вёрстка**
- Все интерактивные элементы ≥ 44×44 (проверить скриптом).
- Горизонтальные чипы-фильтры со `scroll-snap`, без «проскролль ========».
- Таблицы → карточки **с `data-label`** (сейчас подписи пустые).
- Длинные казахские слова: `overflow-wrap: anywhere`, `hyphens: auto`.
- Безопасные зоны: `env(safe-area-inset-*)` для низа и верха.

**B4. PWA и офлайн**
- Иконки 192/512 PNG (сгенерировать из SVG через `sharp` в `tools`), `maskable`.
- `apple-touch-icon` → реальный PNG, `theme-color` для светлой темы.
- `vite-plugin-pwa`: `navigateFallback: /index.html`, `cleanupOutdatedCaches`,
  кнопка «Установить приложение» ( `beforeinstallprompt` ).
- Офлайн-баннер: «Нет сети — работает только ранее открытое».

**B5. Мобильные мелочи**
- Убрать `alert()/confirm()` → `Toast` + `Modal`.
- `input` с `font-size: 16px` (иначе iOS зумит).
- Убрать `:hover`-зависимые подсказки (на тач нет hover).

**Критерий готовности B:** Playwright-прогон на 360×740 и 390×844 без горизонтального
скролла; установка PWA на Android-эмуляторе; Axe mobile — 0 serious.

## 4. Фаза C — ПК-версия (приоритет P1)

**C1. Layout**: на ≥1280px — три колонки: навигация · контент · правая панель
(«Сегодня», «Повторить», «Прогресс по темам», «Достижения»). Правая панель
sticky, скрывается < 1180px.

**C2. Keyboard-first**
- `g e` — экзамен, `g s` — знаки, `g p` — прогресс (последовательность), `?` —
  шпаргалка по клавишам (Sheet), `/` — фокус в поиск.
- В экзамене: `1–4`, `Enter`, `←/→`, `Space` — пауза, `Esc` — выход с подтверждением.
- Видимый фокус на всех интерактивных элементах (не `outline: none`).

**C3. Плотность и столы**
- Переключатель плотности (compact/comfortable) в настройках, сохраняется.
- Таблицы: сортировка по столбцам (штрафы — по сумме/статье), липкая шапка.
- Галерея знаков: 2 режима (плитка/список), сохранение выбора.

**C4. Правая панель** — живые данные: очередь SRS на сегодня, «до экзамена N дней»
(дата, введённая пользователем), топ-3 слабые темы, мини-график за 14 дней.

**Критерий готовности C:** 1280×800 и 1440×900 — нет «лишнего» скролла по
вертикали на главной; все действия доступны с клавиатуры (проверено e2e).

## 5. Фаза D — Учебный функционал (главная ценность)

**D1. Диагностика (placement)** — 12 вопросов, 5 минут, по 3 темам из разных
групп → карта «знаю / учу / не знаю» и персональный план на 7 дней.
Хранение: `placement` в профиле; пересдача — раз в 14 дней.

**D2. План подготовки**
- «До экзамена» — дата; алгоритм раскидывает темы по дням с учётом SRS-очереди
  (не больше N новых вопросов в день, сначала — просроченные).
- Экран «Сегодня»: 3 задачи (20–25 вопросов): повтор · новая тема · слабое место.

**D3. Режим «Разбор»**
- К каждому объяснению: «почему остальные неверны» (we need data: поле
  `optionNotes` в схеме, опционально), «запомнить» мнемоника, «связанные знаки».
- Отметка «понял / не понял» → влияет на SRS (штраф за «не понял»).

**D4. Охота за ошибками**
- Серия «3 подряд правильно» → вопрос уходит из очереди на 7 дней.
- Ошибка → возврат через 10 минут в той же сессии + карточка в «Работа над ошибками».
- Экран «Красная зона»: темы с точностью < 60% и ≥ 5 ответов.

**D5. Прогноз готовности**
- Формула: `P = w1·точность + w2·покрытие тем + w3·(1 − свежесть ошибок) + w4·скорость`,
  откалибровать на своих данных (цель: 80%+ у тех, кто реально сдаёт).
- Шкала «не готов / близко / готов» + «что даст максимум баллов».

**D6. Практика в офлайне и «режим дороги»**
- «Слушать вопрос» (Web Speech API) — руки заняты.
- Крупный «режим на ходу» (только экран вопроса + 2 огромные кнопки).

**D7. Контент и обратная связь**
- Кнопка «Сообщить об ошибке» в каждом вопросе → очередь в localStorage →
  экспорт JSON для автора (без сервера).
- «Предложить улучшение» — то же.
- Админ-страница `/admin` за паролем-заглушкой: список сообщений, импорт, экспорт.

**D8. Социальное (без сервера)**
- «Вызов друга»: ссылка `?c=<base64 результата>` → у друга открывается экран
  «побей результат» с тем же набором вопросов.
- Неделя с друзьями: сравнение по ссылке, без рейтинга незнакомцев.

**D9. Доступность**
- Настройка «Крупный текст» (масштаб 1.15/1.3), «Высокий контраст»,
  «Меньше анимаций» (уже есть частично).
- Полная озвучка вопросов и объяснений.

**Критерий готовности D:** 5 новых экранов работают на 3 языках; диагностика
пишется в профиль; план на день учитывает SRS; экспорт ошибок скачивается.

## 6. Фаза E — Производительность, SEO, надёжность

**E1. Бандл**: split i18n по языкам (dynamic import), `manualChunks` для
`recharts` не нужен, но `dexie` — в отдельный чанк (уже), `lucide` — tree-shake
проверить (`lucide-react` импортировать поштучно, уже так).
**E2. Изображения**: SVG-знаки — спрайт или `?url` с `loading=lazy`,
`decoding=async`; убрать `filter: drop-shadow` на 65 плитках (перф).
**E3. Виртуализация**: галерея знаков (65 ок, но с фильтрами ок), прогресс —
история попыток.
**E4. SEO**: prerender `sitemap.xml` + `robots.txt` + JSON-LD `FAQPage`/`Article`
для `/reference`, `/signs/:code`; canonical; OG-картинка.
**E5. Надёжность**: `ErrorBoundary` на каждый маршрут, `try/catch` вокруг Dexie,
версионирование схемы БД + миграции, `AbortController` в fetch.
**E6. Аналитика без cookies**: только локальные счётчики (события в Dexie),
экспорт «мои метрики» JSON.

**Критерий готовности E:** Lighthouse ≥ 90/95/100/90; bundle ≤ 95 KB gzip;
PWA устанавливается; офлайн-экзамен работает.

## 7. Фаза F — Масштабная проверка (после всех обновлений)

2. `eslint` (включить: `react-hooks/exhaustive-deps`, `no-floating-promises`).
3. `vitest run` — unit + storage (с `fake-indexeddb`) + компонентные.
4. `cargo fmt --check`, `cargo clippy -D warnings`, `cargo test`.
5. `node tools/build-content.mjs --check` — контент валиден.
6. `npm run build` — успешно, бюджет по размеру чанков (`size-limit`).
7. Playwright: 8 e2e-сценариев (экзамен до конца, провал, «переиграть ошибки»,
  билет дня стабилен, офлайн, клавиатура, смена языка, PWA manifest).
8. Axe-core: 0 serious/critical на 11 маршрутах × 2 темы.
9. Lighthouse CI: 5 маршрутов × mobile.

### F2. Вручную (чек-лист)
- **Матрица**: 360×640, 390×844, 768×1024, 1280×800, 1440×900; тёмная/светлая.
- **Сценарии**: первый визит без данных → экзамен → ошибка → разбор → «переиграть»
  → профиль → sync-код на «втором устройстве» (новый контекст браузера) → возврат.
- **Крайние случаи**: 0 попыток, 1000 попыток, пустой профиль, битый sync-код,
  отключённый IndexedDB (приватный режим Safari), медленная сеть (Slow 3G),
  офлайн посреди экзамена, смена языка посреди экзамена, поворот экрана.
- **Контент**: каждый знак открывается, у каждого вопроса есть объяснение и
  ссылка на пункт; нет « битых » ссылок (`tools/build-content.mjs` + скрипт
  проверки ссылок).

### F3. Регресс-тесты на найденные баги
Каждый исправленный дефект → тест, который падает до фикса и зелёный после.
